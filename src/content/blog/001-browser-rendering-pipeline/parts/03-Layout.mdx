## Layout (or Reflow)

Once every element has computed styles, the browser's next job is to figure out where everything actually goes.  
This stage is called Layout, or Reflow when it runs again after changes.

<br />

### What happens here

1. The browser builds a **Layout Tree** (also called a **Frame Tree** in Gecko).  
   An in-memory structure derived from the DOM + computed styles, but filtered down to only **visible, renderable elements**.

2. Each node in the tree gets precise geometry from the box model: its position, width, height, padding, borders, margins, line breaks, etc.

3. Inline text is measured and split into line boxes.

4. Relative values (`%`, `em`, `vh`) are resolved against parents and viewport sizes.

<br />

### Why “Reflow”?

Because this process isn't one-and-done.

If you resize the window, insert content, or change styles that affect geometry, the browser may need to run layout again.  
Depending on what changed, this can affect just one subtree or cascade through the entire page.

<br />

Example:

{/* prettier-ignore */}
```html
<div class="box">
  Hello
</div>
```

```css
.box {
  width: 200px;
  padding: 10px;
  margin-left: 100px;
}
```

Layout tree entry (conceptual):

```
DIV.box
  x: 100
  y: 0
  width: 200
  height: 20
  padding: 10
```

The browser now knows exactly where that box and its content should sit on the page.

<br />

### Why this stage can be expensive

Layout depends on relationships between elements (flexbox, grid, percentages).  
A change in one place can ripple through siblings, children, or even the whole document.

Some DOM APIs like `getBoundingClientRect()` or `offsetWidth` can also force a **synchronous layout**, because the browser must flush pending changes and give you an accurate number.  
That means JS execution pauses until the layout tree is up to date.

<br />

> **Note on `offsetWidth`:**  
> This property returns an element's rendered width (content + padding + borders, no margins).  
> But reading it forces the browser to run layout synchronously so the number is correct, pausing JS execution until the layout tree is fresh.  
> Developers sometimes exploit this:
>
> ```js
> el.classList.remove("animate");
> void el.offsetWidth; // force layout flush
> el.classList.add("animate"); // animation restarts
> ```
>
> Here `offsetWidth` is used as a hack to restart a CSS animation. Handy trick, but it comes with a performance cost if overused.
> Used sparingly it's usually fine, but in loops or animation frames it can cause repeated reflows and jank.

<br />

### Output of this stage

The Layout Tree, an in-memory structure with precise box positions and dimensions.

This becomes the input for the Paint stage, where the browser actually starts drawing things.
