## Style (a.k.a. Style Recalculation)

Once the browser has both the DOM and the CSSOM, it can finally decide what each element should look like. This stage is often called style calculation or style recalc.

What happens here

The browser walks the DOM tree and matches each node against rules in the CSSOM.

It applies the cascade (specificity, importance, source order) and inheritance rules.

Custom properties (`--variables`) are resolved.

The result is the computed style for each element: every property now has an absolute, resolved value.

Example

```html
<div class="box">Hello</div>
```

```css
:root {
  --main-color: red;
}
.box {
  color: var(--main-color);
  font-size: 1rem;
}
```

Computed style for the `<div class="box">`:

```yml
color: rgb(255, 0, 0)
font-size: 16px
display: block
margin: 0px
```

Notice how relative values (`1rem, var(--main-color)`) are turned into absolute values (`16px, rgb(255,0,0)`).

CSS Variables and Scope

This is where CSS variables behave differently from normal properties:

If you update a variable in JS:

```javascript
element.style.setProperty("--main-color", "blue");
```

the browser only recalculates styles for nodes where that variable is used.

If the variable is defined at :root, then every descendant that uses it may need to be recalculated.

If the variable is scoped on a single element, only that element and its children are affected.

This is why scoping variables wisely matters: updating a root-level variable every frame can trigger style recalculations across the entire page.

Output of this stage

A computed style map: each DOM element has a resolved set of styles (think of it as a big object with key-value pairs).

This map becomes the input for the next stage: layout, where geometry (positions and sizes) is calculated.
