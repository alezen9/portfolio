## 6. Display (Buffers & Vsync)

At this point, the compositor has assembled all the layers into a single frame.  
The last step is to actually put those pixels on the screen.

<br />

### Double buffering

The GPU maintains two buffers:

- ==Front buffer==: currently being scanned out to the display.
- ==Back buffer==: where the next frame is rendered.

<br />

Once the back buffer is ready, the pointers are swapped, the back becomes the new front, and the old front is reused as the new back.  
This happens in sync with the monitor's refresh (VSync) so the screen never shows half of one frame and half of another (tearing).

<br />

### Triple buffering

Some systems use three buffers: one front + two backs.  
This allows the GPU to start rendering a new frame even if one back buffer is waiting for VSync.

**Benefit:** smoother scheduling, less stutter.  
**Trade-off:** more GPU memory, and input can feel slightly less responsive. A freshly rendered frame might not be shown until the next refresh cycle, adding up to one extra frame of latency.

> **Note:** Many platforms dynamically switch between double and triple buffering depending on GPU load and timing conditions.

<br />

### Why VSync matters

Monitors refresh at fixed intervals (60Hz, 120Hz, 144Hz, etc.).

- If the browser delivers a frame before the deadline, it's shown smoothly.
- If it misses, that frame is delayed until the next refresh or dropped, causing a visible ==stutter== hence breaking smooth motion.
- With VSync off: frames can be shown as soon as they're ready, but you risk ==tearing== (two frames shown in one refresh represented as a jagged split across the screen).

<br />

This is why we talk about the frame budget: ~16ms per frame at 60Hz, ~8ms at 120Hz.  
Consistent pacing matters as much as raw FPS, uneven frame times look choppy even if the average FPS is “high.”

==Latency== is the third piece of the puzzle: the delay between input (e.g. a keypress) and when its effect becomes visible.  
Buffering strategies and missed VSync deadlines can both increase it.

<br />

### End of the journey

From raw HTML + CSS text, we went through:

1. **Parsing** &rarr; DOM + CSSOM
2. **Style** &rarr; computed styles
3. **Layout** &rarr; geometry (layout tree)
4. **Paint** &rarr; display list &rarr; rasterized tiles
5. **Compositing** &rarr; layers assembled by compositor thread
6. **Display** &rarr; buffers swapped on VSync

That's how your code turns into pixels on the screen.
